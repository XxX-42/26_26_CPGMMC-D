### 2.2 解释性、溯源性最高路线

**仍然选择同一条路线。**

解释性不取决于“是不是所有变量都放进 Gurobi”，而取决于能否清楚说明每个对象和约束。

例如一条电池约束可以直接写成：

$$
\text{同一电池的“任务占用—充至满电”区间不相交}.
$$

它比在论文中展开数千个大 \(M\) 先后顺序约束更容易解释，也没有减少数学约束的严格性。OR-Tools 官方排程示例采用区间变量、先后关系和 `NoOverlap` 表达这类互斥资源。([Google for Developers][1])

## 5. 问题一：完整研究路线

### 模型

**最大安全载荷一维可行域＋同服务区可行子集集合划分模型。**

对服务区 \(i\)、机型 \(g\)，定义单点往返能耗：

$$
E^{RT}_{ig}(q)
=
E_{g,O01,i}(q)+E_{g,i,O01}(0).
$$

最大安全载荷：

$$
q^*_{ig}
=
\max\left\{
q\in[0,Q_g]:
E^{RT}_{ig}(q)\le(1-\rho_g)E_g^{use}
\right\}.
$$

这里的连续安全载荷是**飞行能量与额定质量意义下的上限**。货箱体积约束随后在离散组批中检查，不能在没有货物密度定义时，把体积直接折成连续载质量。

对于服务区 \(i\) 的货箱集合 \(K_i\)，生成候选：

$$
c=(i,g,S),\qquad \varnothing\ne S\subseteq K_i.
$$

只保留同时满足质量、体积和返航余量的候选。

决策变量：

$$
x_c\in\{0,1\}.
$$

每箱唯一覆盖：

$$
\sum_{c:k\in S_c}x_c=1,\qquad \forall k.
$$

正式目标：

$$
\operatorname{lexmin}
\left(
\sum_c x_c,\;
\sum_c E_cx_c,\;
\sum_c T_c^{op}x_c
\right).
$$

即：**先少架次，再低能耗，再短累计作业时间**。这是本文选择的优先关系，题面允许解释指标的权衡或优先关系，并没有强制给出这一顺序。

### 算法

```text
能耗单调性检查
→ 空载与额定满载边界检查
→ 必要时二分求安全载荷
→ DFS 枚举可行货箱子集
→ 按服务区分解求集合划分 MILP
→ 汇总与独立复验
```

必须区分三种边界：

| 情形                 | 正确输出                                         |
| -------------------- | ------------------------------------------------ |
| 空载往返也不满足余量 | `UNREACHABLE`，不能输出“安全载荷为 0 且可行” |
| 额定满载仍满足余量   | \(q^*=Q_g\)，不要求能量约束恰好取等号            |
| 能量先成为限制       | 输出可行下界、不可行上界和二分区间宽度           |

### 为什么选择它

Q1 的货箱不能跨服务区组批，因此可以按 15 个服务区分解，而不必直接枚举 80 箱的所有子集。

复杂度主要与各区箱数 \(n_i\) 有关：

$$
O\!\left(3\sum_{i=1}^{15}2^{n_i}\right).
$$

**平均每区约几箱，不代表最大箱数也只有几箱。** 首先读取 \(n_{\max}\)，再决定枚举预算。

完整枚举且 MILP 证明最优时，可以对 Q1 给出精确性结论；GA 没有为这个结构带来必要收益，却会增加编码和重复覆盖修复工作。

### 技术路线、输入、输出与软件

| 项目          | 冻结内容                                                                |
| ------------- | ----------------------------------------------------------------------- |
| Python/solver | NumPy＋自定义二分与 DFS＋Gurobi                                         |
| 输入          | 节点、DEM、机型参数、逐箱质量体积、余量要求                             |
| 输出          | 45 项安全载荷状态；Q1 组批；逐架次能耗、时间、SOC；最优性日志           |
| 必做实验      | 返航余量变化对安全载荷、架次数、能耗和机型组合的影响                    |
| 运行预算      | 物理预计算完成后，先给 Q1 求解约 5 分钟预算；这是工程预算，不是实测保证 |

### Validator

重新计算每个候选的箱集合、目的区、质量、体积、往返航段、能耗和返航 SOC，检查全部 80 箱恰好出现一次。

**Q1 最少单点架次数不能直接当作 Q2 多点运输最少架次数的全局下界。** Q2 的访问模式不同，二者可行域不同。

| ---- | ----------------------------------------------------------------------------------------------------- |
| 好   | 45 项状态全部有计算证据；80 箱唯一覆盖；架次数最优性证明完成；后续目标报告 gap；至少 5 个余量设置完成 |
| 中   | 全部硬约束通过，但部分目标只取得可行解，或尚未证明最优                                                |
| 坏   | 漏箱、重复、跨区组批、能量越界、把不可达当零载荷可达，或物理公式尚未核实                              |

### 主要风险

不是 MILP 本身，而是能耗口径、地形最大值和“空载返程”算错。出现这些问题必须退回 Gate-0。

## 6. 问题二：完整研究路线

### 模型

**有限候选架次上的箱级集合划分与双资源区间排程一体化模型。**

正式采用：

> **一个 CP-SAT 模型同时选择架次、分配实体无人机与电池、确定开始时间。**

不采用：

```text
Gurobi 先固定路线
→ CP-SAT 再尝试排程
→ 排不出来后反复退回
```

### 候选架次的数据结构

每个候选 \(p\) 必须包含：

```text
candidate_id
机型
货箱集合
服务区访问顺序
逐航段剩余载荷
逐阶段三维轨迹
准备、飞行、交付、返回与周转事件
每箱交付完成时间偏移
运输能耗与返航 SOC
实体机再次可用时间偏移
电池再次满电可用时间偏移
原始参数与公式来源
```

**“返回 O01”“无人机完成周转”“电池充满”是三个不同事件。**

题面规定的 Q2 makespan 是所有运输无人机最后返回 O01 的最晚时刻，而不是所有电池充满的时刻。

### 候选生成算法

正式使用**确定性的可行扩展与束搜索**，不使用 ALNS。

```text
所有可行单箱、单服务区批次作为种子
→ 按时限和空间邻近关系生成双点架次
→ 保留有限数量优良前缀，扩展多点访问
→ 物理、容量、时限必要条件剪枝
→ 候选去重与受限支配筛选
```

初始工程参数冻结为：

| 参数                 | 初始值或策略                                         |
| -------------------- | ---------------------------------------------------- |
| 活跃候选池           | 500–2000 条                                         |
| 单个扩展层的保留宽度 | 40                                                   |
| 初始多点深度         | 先扩展到 4 个服务区                                  |
| 更长路线             | 只在未覆盖、时限困难或明显可改善的任务上继续扩展     |
| 存档候选池           | 上限约 20000 条，不全部直接投入排程                  |
| 必须保留             | 当前完整可行解、每箱必要替代候选、关键医疗与首批候选 |

这些是**候选搜索限制，不是官方“最多访问四点”约束**。论文必须承认 Q2 是受限候选池上的优化。

### 决策变量与约束

选择架次：

$$
y_p\in\{0,1\}.
$$

每箱恰好由一个被选架次运输：

$$
\sum_{p:k\in K_p}y_p=1.
$$

架次开始时间：

$$
s_p\ge0.
$$

对选中的架次，分配一个兼容实体机和一块兼容电池：

$$
\sum_{u\in U_{g_p}}a_{pu}=y_p,\qquad
\sum_{b\in B_{g_p}}b_{pb}=y_p.
$$

交付完成时刻：

$$
D_k=s_p+\delta_{pk}.
$$

医疗与首批货箱的硬截止统一为：

$$
d_k^{hard}
=
\min
\left\{
d_k^{exp}\ \text{若为医疗箱},
\quad
d_k^{first}\ \text{若为首批箱}
\right\}.
$$

同时属于两类的货箱，必须满足更早的那个要求。题面对医疗、首批和其他物资的语义区分是明确的。

### 无人机与电池区间

为每个实体机建立可选占用区间：

$$
I^U_p=[s_p,\ s_p+\tau^U_p).
$$

为每块电池建立可选不可复用区间：

$$
I^B_p=[s_p,\ s_p+\tau^B_p).
$$

其中，\(\tau^U_p\) 包含该实体机实际需要的周转；\(\tau^B_p\) 包含任务占用、必要拆换和充至 100% 的时间。具体准备、装卸和周转是否互相包含，必须按原始字段定义处理，不能重复累加。

同一物理资源对应的区间：

```python
model.add_no_overlap(intervals)
```

可选机器分配与区间变量的实现，可直接依据 OR-Tools 官方 flexible job shop 示例组织，而不是自行发明一层复杂排程接口。([GitHub][2])

电池在每次起飞前都是满电，因此候选架次的返航 SOC 和充电时长可以提前计算。题面允许不同能源资源并行充电，**不额外虚构“只有一个充电位”的全局互斥约束**。

### 时间整数化的正式规则

CP-SAT 的约束使用整数，因此整数化必须在统一适配层完成。([Google for Developers][3])

冻结为：

* 开始时刻采用 **1 毫秒整数刻度**。
* 资源占用长度向上取整。
* 硬截止向下取整。
* 物理轨迹仍使用原始浮点飞行时间，不把每个飞行阶段分别取整后改变官方飞行速度。
* 取整产生的富余仅作为资源预留，不作为额外空中悬停。
* 能量硬可行性使用未取整的物理计算；整数能量只用于目标比较，并记录量化误差界。

因此，最终验证必须回到真实物理时间，不能只验证整数排程模型。

### 输入、输出、复杂度与软件

| 项目       | 冻结内容                                                 |
| ---------- | -------------------------------------------------------- |
| 输入       | 完整候选架次、逐箱时限、实体机与电池库存、充电规则       |
| 输出       | Q2 运输架次、逐箱交付、实体机时间线、电池与充电时间线    |
| 软件       | OR-Tools CP-SAT；公共物理模块；NumPy                     |
| 模型规模   | 随候选数与兼容资源数增长；不显式展开所有任务两两先后变量 |
| 最优性范围 | 当前候选池与时间刻度下的模型                             |
| 首要目标   | 先得到完整可行调度，再优化                               |

### Validator

至少输出：

```text
boxes_missing = 0
boxes_duplicated = 0
hard_deadline_violations = 0
drone_overlap = 0
battery_overlap = 0
charging_conflicts = 0
battery_type_mismatch = 0
reused_before_full_charge = 0
energy_reserve_violations = 0
```

再独立重算总逾期时间、makespan、能耗与架次数。

### 好／中／坏标准与风险

**好：**硬约束全部通过，优于或不劣于可行 baseline，记录每层目标的 incumbent、bound、求解时间和候选池规模。

**中：**完整可行，但仅为受限池中的一般质量解，或缺少充分比较。

**坏：**任何硬违规；尤其是“路线可行但电池排不出来”，不能当作 Q2 已完成。

主要风险是候选池遗漏关键路线、时间字段含义混淆和资源区间起止错误，而不是“没有 GPU”。

## 7. 问题三：完整研究路线

### 7.1 模型与正式算法

**模型：地形约束下的通信区间覆盖与运输—中继资源协调模型。**

**算法：候选中继离散化＋CP-SAT 覆盖排程＋确定性冲突修复＋连续区间验证。**

这是全题的核心，但不构造连续三维位置、箱子分配、电池充电和全部时序一次性联合的巨大 MINLP。

---

### 7.2 运输轨迹如何形成

直接由 Q2/Q3 当前候选架次和公共物理模块重建：

$$
\mathbf{x}_p(t).
$$

每条架次分成：

```text
准备
→ 爬升
→ 水平巡航
→ 下降
→ 交付作业
→ 下一段重新爬升
→ …
→ 返回 O01
```

连续通信检查覆盖全部实际飞行和交付作业阶段。每次交付后，下一航段使用更新后的载荷。

运输航段的巡航海拔必须取所经原始 DEM 像元最高值加 50 m，服务区作业高度为地面以上 30 m。

**不允许为了通信更好而偷偷绕山改变题面规定的水平直线航段。** 允许修改的是访问顺序、组批、机型和开始时刻。

---

### 7.3 G01 直连如何检测

G01 的三维端点不是 O01 地面点，而是：

$$
z_{G01}=z_{O01}^{ground}+h_{antenna}.
$$

先计算双向允许损耗：

$$
L^{bi}_{ab}
=
\min\{L^{max}_{a\to b},L^{max}_{b\to a}\}.
$$

再计算：

$$
L^{path}_{ab}(t)
=
32.45+20\log_{10} f_{\mathrm{MHz}}
+20\log_{10}D_{\mathrm{km}}(t)
+b_{ab}(t)L_{obs}.
$$

链路余量：

$$
m_{ab}(t)=L^{bi}_{ab}-L^{path}_{ab}(t).
$$

链路可用条件：

$$
m_{ab}(t)\ge0.
$$

**有遮挡并不必然断链；无遮挡也不必然可用。** 前者还取决于附加损耗后的预算，后者还可能因距离过远而失败。

---

### 7.4 先用距离界减少 DEM 视线计算

这一步由官方链路公式直接推导，不增加新传播模型。

对某种双向接口，定义：

$$
R_{\mathrm{clear}}
=
10^{\frac{L^{bi}-32.45-20\log_{10}f}{20}},
$$

$$
R_{\mathrm{blocked}}
=
R_{\mathrm{clear}}10^{-L_{obs}/20}.
$$

单位为 km。

于是：

| 三维距离                      | 判定                               |
| ----------------------------- | ---------------------------------- |
| \(D\le R_{\mathrm{blocked}}\) | 即使按遮挡损耗计算，链路仍满足预算 |
| \(D>R_{\mathrm{clear}}\)      | 即使无遮挡，也不满足预算           |
| 两者之间                      | 才需要 DEM 遮挡判定                |

这样可以避免对每个候选、每个位置都执行昂贵的视线穿栅格计算。

这些半径目前**不能数值化**，因为原始发射功率、天线增益和接口参数尚未读取。

---

### 7.5 Relay XY 和高度如何生成

**XY 正式生成规则：**

```text
相关区域的 500 m 粗网格
＋服务区附近候选
＋运输直连盲区附近候选
＋遮挡山脊与局部高地候选
→ 回传、能量、范围与相关性筛选
→ 被选点附近局部细化
```

不是在整个 DEM 的每一个像元上放中继。

**高度正式采用固定 AGL 层级＋局部细化：**

```text
初始层级：50、100、150、200、250、300 m
实际保留：不超过原始附件规定的上限
局部细化：高度步长 25 m，再到 12.5 m
```

上述 300 m 来自审计摘要，正式程序仍从原始表读取上限。

不采用“高度越高越好”的单调假设：升高可能消除遮挡，也会增加距离、飞行和能耗。

**一个必须显式处理的几何边界：**若中继悬停海拔高于按往返航段地形算出的巡航海拔，当前正文没有完整展开这一特殊衔接过程。正式保守候选集先剔除会造成负爬升或负下降的选项；原始附件若有明确衔接规定，按其补全。不能在代码里悄悄改变巡航规则。

初始筛选后，目标保留 **200–800 个三维候选**；超过约 1500 个时先筛选，不继续盲目增点。这是计算预算，不是保证可行的候选数量。

---

### 7.6 连续空间怎样变成离散优化

空间离散到有限候选位置 \(r\)，时间不采用整天逐秒展开，而采用**通信需求事件区间**。

对运输架次 \(p\)，提取直连不可用区间：

$$
\mathcal U_p=\{[a_{p1},b_{p1}],\ldots\}.
$$

候选中继 \(r\) 能保障某区间，必须同时满足：

$$
A(\mathbf x_p(t),r)=1,
\qquad
A(r,G01)=1,
\qquad \forall t\ \text{属于该区间}.
$$

**缓存以“航段几何进度—覆盖区间”为主，而不是以全局开始时刻为主。**

同一航段换一个出发时间，只需平移覆盖区间，不必重新计算地形；更换载荷也不应无理由重算同一几何视线。机型通信接口不同时，分别缓存其预算结果。

---

### 7.7 Relay 任务如何构造和排程

每个中继选项：

$$
\omega=
(r,\ t^{start},t^{ready},t^{end},t^{return}).
$$

含义分别为任务开始、建链完成、服务结束和返回时刻。

每个选项预先确定：

```text
位置与悬停海拔
准备、去程、建链、服务、返程与周转
可覆盖的运输通信区间
能耗与返航 SOC
能源组件再次满电的时刻
```

候选服务窗口从盲区的开始、结束和相邻需求事件生成；只保留连续服务期间能量可行的窗口。中间即使没有运输机需要中继，只要该架中继仍悬停，就必须计算这段悬停能耗。

选择变量：

$$
z_\omega\in\{0,1\}.
$$

每个通信需求区间必须被覆盖：

$$
\sum_{\omega}C_{j\omega}z_\omega\ge1.
$$

之后联合分配：

* 实体中继无人机；
* 兼容能源组件；
* 对应任务占用和充电不可复用区间。

仍然使用 CP-SAT 的区间与互斥资源模型。

**不能让中继在负时间提前出发。** 第一段保障必须满足实际准备、飞行和建链时间。

当前可读题面没有给出“一架中继只能同时服务一架运输机”的限制。若原始通信表也没有容量限制，不能自行加上这个约束；但每架运输机同一时刻只能采用一个保障来源，且禁止 relay-relay 多跳。

---

### 7.8 中继能耗如何处理

统一分解为：

$$
E^R_\omega
=
E^{cruise}_\omega
+
E^{climb}_\omega
+
E^{hover+communication}_\omega.
$$

巡航功率与时间的单位必须一致；功率为 kW、时间为秒时，能量换算为：

$$
E=P\,t/3600.
$$

爬升质量使用计划起飞总质量，不使用运输货箱质量。准备、建链、悬停和周转的具体含义由原始中继表确定。题面对中继的这些能源组成有明确描述。

建链阶段若未单独给功耗定义，必须列入假设台账；保守处理为建链期间计悬停及相关通信功耗，不能当作免费悬停。这是补充假设，不冒充官方明示公式。

---

### 7.9 Q2 方案无法被中继保障时怎么办

**正式采用运输—中继冲突驱动迭代修复。**

```text
Q2 完整可行运输方案
→ 生成直连盲区
→ 求中继覆盖与资源排程
→ 提取失败原因
→ 只修改相关运输任务
→ 重新排运输资源并检查时限
→ 重建受影响的中继时间选项
→ 再求中继
→ 完整验证后更新当前最好可行解
```

修复顺序冻结为：

| 冲突类型               | 优先处理                                           |
| ---------------------- | -------------------------------------------------- |
| 中继来不及建链         | 调整相关运输开始时刻，重新检查硬截止               |
| 多个盲区同时争用中继机 | 错峰运输或改变相关访问顺序                         |
| 一个中继任务续航不足   | 缩短窗口、安排接替中继、拆分相关运输架次           |
| 某段没有候选能覆盖     | 定向细化空间候选；再考虑换访问顺序或拆分路线       |
| 能源组件来不及充满     | 调整中继窗口及相关运输时刻，不能直接允许未满电复用 |

修复算子只保留：**开始时间移动、访问顺序替换、架次拆分、候选架次替换**。

不建立复杂 ALNS 接受机制。

这是一个协调优化算法，**不是全局最优性保证，也不称为已实现 Benders 分解**。受限中继候选集无解，也不能证明连续空间不存在解。

### 7.10 连续通信如何独立验证

**“每 5 m 采样没有断链”不等于已经证明全过程连续通信。**

正式验证采用：

> **阶段边界检查＋自适应区间划分＋区间链路下界证据＋加密采样交叉检查。**

对固定网关或悬停中继 \(r\)，运输机在一个线性运动时间段 \([a,b]\) 内：

$$
\mathbf x(t)=\mathbf x(a)+\theta(t)\big[\mathbf x(b)-\mathbf x(a)\big].
$$

距离的最大值可由端点给出：

$$
D_{\max}
=
\max\{\|\mathbf x(a)-r\|,\|\mathbf x(b)-r\|\}.
$$

验证分两级。

**第一级：最坏遮挡损耗也能通过。**

按 \(D_{\max}\) 和 \(b=1\) 计算仍满足预算，则整个时间段有可用性证据，不需要逐时检查遮挡变化。

**第二级：需要无遮挡才能通过。**

固定端点 \(r\) 与移动端点之间的全部视线，组成以

$$
r,\mathbf x(a),\mathbf x(b)
$$

为顶点的三角形扫掠区域。将其与沿途 DEM 像元对应的地形柱体做保守相交检查；只有能证明整段没有地形遮挡，才使用 \(b=0\) 的区间下界。

原 DEM 像元采用明确记录的常高解释；投影后的足迹用保守包络处理，不通过平滑或降低高程获得虚假视距。

无法判定的区间继续细分。达到细分预算仍无法证明时：

```text
状态 = UNCERTIFIED
```

**不能把它记为通信正常。**

最终必须同时满足：

```text
communication_outage_duration_upper_bound = 0
uncertified_duration = 0
phase_boundary_violations = 0
handover_violations = 0
minimum_certified_link_margin >= 0 dB
```

这里的零，是**声明的 DEM 和传播模型下的数值可行性证据**，不是对现实风雨、干扰与未建模地物的保证。

对于中继链路，保障余量取两跳余量的较小值。通信切换事件单独定位和检查，不能因为某个断点持续时间为零就忽略它。

加密交叉检查使用 10 m、5 m、2.5 m 三级空间尺度，并限制时间步长；最后两级最小采样余量差目标不超过 0.1 dB。**加密收敛是补充证据，不替代上述区间判定。**

| 项目           | 内容                                                                           |

| 输入           | Q2 初解、可替代运输候选、原 DEM、通信参数、中继机与组件参数                    |
| 输出           | Q3 最终运输方案、中继任务、通信保障区间、全部资源时间线、通信证据              |
| 软件           | NumPy、rasterio、pyproj、几何模块、CP-SAT                                      |
| 复杂度主要来源 | 相关航段×中继候选×必要地形检查，以及中继选项排程                             |
| 控制手段       | 距离界预筛、航段缓存、稀疏覆盖区间、候选上限、局部重算                         |
| 好             | 全部区间可证；零资源冲突；候选细化后结论稳定；与冻结运输 baseline 有可解释比较 |
| 中             | 已完整可行，但余量小、候选收敛或改进证据不足                                   |
| 坏             | 精细验证出现断链；存在未认证区间；中继未到位就提供服务；两跳不同步             |

**Q3 正式完成的定义不是“中继表填好了”，而是运输、时限、资源、能源和全过程通信共同可行。**

## 8. 问题四：完整研究路线

### 模型

**固定任务依赖图上的精确分区与资源区间回放模型。**

先冻结 Q3 的：

```text
货箱归属
访问顺序
运输与中继任务时间
中继位置
通信保障关系
机型与任务物理属性
```

然后构造服务区依赖图。

### 同一运输架次的 must-link

同一运输架次访问的全部服务区必须同组，这是题面明确要求：

$$
g(i)=g(j),\qquad i,j\in S_p.
$$

用并查集合并，再取传递闭包。

### 同一固定 relay sortie 是否引入跨运输架次依赖

**本次正式采用保守解释：会。**

必须区分：

| 层次         | 内容                                                                                 |
| ------------ | ------------------------------------------------------------------------------------ |
| 题面明确要求 | 固定中继任务安排和通信保障关系，任务执行期间资源不得跨组调配                         |
| 本文合理解释 | 同一个已经冻结、不可拆分的中继架次若保障多条运输架次，这些运输架次对应服务区也应同组 |
| 不允许的做法 | 将同一个固定中继架次免费复制到多个组，或称其同时属于多个独立任务组                   |

理由是：若任务不拆、不复制，且执行资源不能跨组，这个共同中继任务必须归属于一个执行单元。

**但同一实体中继机执行的不同中继架次，不自动构成 must-link。** 否则会把“任务关系固定”和“原资源编号永远不能改变”混为一谈。

资源重新编号的正式解释为：

> Q4 可以为独立执行重新绑定同型号资源编号，但不得修改任务本身、类型、时间或通信关系。每组使用自己的资源编号，不跨组共享。

这是对“核算独立资源需求”的建模解释；题面没有逐字规定必须保留 Q3 的具体电池或无人机编号。

### 必须提前发现的结构性风险

设合并后有 \(M\) 个连通分量。

$$
M<K
$$

时，不存在 \(K\) 个非空任务组。

因此，**Q3 最终冻结前，必须做一次 Q4 可分性预检查，要求当前采用的任务依赖解释下至少有 3 个分量。**

这是为保证四问可交付而增加的方案筛选条件，不是伪称题面给 Q3 增加了一个显式约束。

如果已经冻结的 Q3 只有一个或两个分量，Q4 必须报告结构性不可分，不能在 Q4 里偷偷拆任务。需要修改时，应明确生成新的 Q3 版本，再重新冻结。

### 算法

```text
运输与中继保障依赖建图
→ 并查集压缩为 supernodes
→ 枚举无标签、非空的 2/3 组划分
→ 查表获取各组资源需求
→ 比较缺口、冗余、工作量
→ 输出精确最优分区及资源分配证据
```

最多 15 个分量时，无标签非空划分数为：

$$
S(15,2)=2^{14}-1=16383,
$$

$$
S(15,3)=\frac{3^{15}-3\cdot2^{15}+3}{6}=2375101.
$$

这个规模值得做精确枚举，但不能对每个划分都从头读取 Excel 和回放全部轨迹。应预先缓存每个分量子集的资源需求向量。

### 资源数量如何核算

对资源类型 \(r\)、组 \(j\)：

$$
R_{jr}=\max_t N_{jr}(t),
$$

其中 \(N_{jr}(t)\) 是该组固定任务在时刻 \(t\) 的资源占用数。

电池和能源组件的占用区间必须包含充至满电前的不可复用时间。

在同类资源可互换、区间已经固定的条件下，按开始时间进行区间着色，可以构造出与最大并发数相同的资源分配；因此不仅给“峰值下界”，还给实际资源编号分配作为达到该数量的证据。

区间采用半开形式 \([a,b)\)，同一时刻先释放、再占用。

资源缺口：

$$
Gap_r=\max\left(0,\sum_jR_{jr}-Inventory_r\right).
$$

资源冗余定义为：

$$
Red_r=\sum_jR_{jr}-R_r^{global},
$$

其中 \(R_r^{global}\) 是同一固定任务集合不分组时的最小资源需求。

**资源缺口大于零不是 Q4 硬约束违规。** 题目本来就要求分析超过库存时的缺口及原因。

### 目标、软件、输入输出与验收

正式优先级：

$$
\operatorname{lexmin}
\left(
\sum_r\frac{Gap_r}{\max(1,Inventory_r)},
\quad
\sum_r\frac{Red_r}{\max(1,Inventory_r)},
\quad
\frac{W_{\max}-W_{\min}}{W_{\mathrm{total}}}
\right).
$$

归一化按现有库存衡量相对紧缺程度，不把它解释为采购价格。绝对资源数量和缺口向量必须同时报告。

| 项目 | 内容                                                              |
| ---- | ----------------------------------------------------------------- |
| 软件 | Python 并查集、位掩码、NumPy、区间回放                            |
| 输入 | 冻结 Q3、资源库存、固定的依赖解释                                 |
| 输出 | K=2、K=3 分组；各类资源数量；缺口、冗余、工作量；资源编号分配证据 |
| 好   | 两种分组均完成精确枚举或等价精确搜索，固定任务与资源隔离全部通过  |
| 中   | 合法分区完整，但尚未证明目标最优                                  |
| 坏   | must-link 违规、修改 Q3 时间、跨组共享资源、把资源缺口偷偷压成零  |

Validator 必须输出：

```text
must_link_violations = 0
fixed_Q3_task_changes = 0
cross_group_resource_sharing = 0
```

## 9. 多目标优化最终方案

### 9.1 正式优先级

**医疗与首批要求放在硬约束层，不再作为“可以赔偿的最高权重目标”。**

| 问题 | 硬约束之后的正式目标顺序                                                |
| ---- | ----------------------------------------------------------------------- |
| Q1   | 架次数 → 总能耗 → 累计作业时间                                        |
| Q2   | 普通物资总逾期时长 → 运输 makespan → 运输能耗 → 架次数               |
| Q3   | 普通物资总逾期时长 → 联合 makespan → 运输与中继总能耗 → 两类总架次数 |
| Q4   | 相对库存缺口 → 相对资源冗余 → 工作量不均衡                            |

普通物资及时性正式使用：

$$
F_{\mathrm{late}}
=
\sum_{k\in K_{\mathrm{ordinary}}}
\max(0,D_k-d_k^{exp}).
$$

采用箱级总逾期秒数，不凭空增加人口或类别权重。

### 9.2 实现方式

统一采用**逐层求解、锁定前层目标上界**：

```text
先求硬可行
→ 最小化 F1
→ 保存可行结果，约束 F1 不恶化
→ 最小化 F2
→ …
```

Gurobi 支持层次多目标及目标退化容差；本工程采用显式逐层求解，便于 Gurobi 与 CP-SAT 共用日志和验收逻辑，也避免默认容差引入不易察觉的目标退化。([Gurobi Documentation][4])

必须区分：

* 前层已证明最优：可以称为相应有限模型上的严格词典序最优。
* 前层仅获得可行 incumbent：只能称为**分层限时优化**，不能称为全局词典序最优。

对 Q2/Q3，所有 bound/gap 必须注明候选池与时间离散范围。**受限候选池模型的 bound，不自动是原始完整问题的全局下界。**

### 9.3 权衡实验

正式提交用上述固定顺序。

有时间再做：

$$
F_{\mathrm{late}}\le F_{\mathrm{late}}^*+\varepsilon
$$

下的 makespan—能耗比较。

当 \(F^*=0\) 时，不能只用 \((1+\varepsilon)F^*\) 这种仍然等于零的设置；应使用明确的绝对允许增量。所有医疗与首批硬截止始终不放松。

## 11. 软件与算力

### 11.1 Solver 最终决定

**主方案是 Gurobi＋CP-SAT，但按问题分工。**

| 比较项              | 全 Gurobi                        | 本次采用的按问题分工                      |
| ------------------- | -------------------------------- | ----------------------------------------- |
| Q1 集合划分         | 合适                             | Gurobi                                    |
| Q2 多候选双资源排程 | 需要设计较多互斥先后关系与界     | CP-SAT 在一个模型内完成                   |
| Q3 覆盖与资源排程   | 可以做，但容易重新写一套时序约束 | 复用 Q2 的 CP-SAT 引擎                    |
| 接口复杂度          | 单 solver，但时序建模工作多      | Q1 只输出普通数据，不与排程器迭代交换模型 |
| 不可行诊断          | 可用 IIS                         | 物理证据、分层约束检查和冲突区间共同诊断  |
| 许可证风险          | 影响全部模型                     | 只影响 Q1，可立即替换                     |

Gurobi 的 IIS 可用于定位不可行子系统，但它不是自动修复工具，MIP 上的诊断也可能昂贵。([Gurobi Documentation][5])

**许可证或接口失败时的最简单降级：**

* Q1 的集合划分改由 HiGHS 求解。
* Q2/Q3 的 CP-SAT 引擎不变。
* 不临时重构为全 Gurobi。

HiGHS 官方提供 LP、MIP 等求解能力，可作为这个线性集合划分接口的备用。([HiGHS][6])

### 11.2 CPU/GPU 判断

| 模块              | CPU 需求                          | GPU 判断                   | 云资源需求                    |
| ----------------- | --------------------------------- | -------------------------- | ----------------------------- |
| Q1                | 单核预处理＋CPU MILP              | **不需要**           | 通常无                        |
| Q2                | CPU CP-SAT，适度多线程            | **不需要**           | 本地求解确有瓶颈后再考虑 CPU  |
| Q3                | DEM 几何、LOS、区间预计算、CP-SAT | **不需要**           | 真正瓶颈是 CPU 计算与缓存组织 |
| Q4                | 位掩码、区间统计、枚举            | **几乎没有必要收益** | 通常无                        |
| 绘图、Excel、验证 | CPU、内存、磁盘                   | **不需要**           | 无                            |

不能再使用“Gurobi 完全不支持 GPU”这个过时理由：其官方在 2026 年已提供 GPU-enabled PDHG 相关实现，主要面向 LP。但这不构成给本题的离散排程与几何验证工程租 GPU 的理由。([Gurobi Help Center][7])

**硬件执行决定：**

本地高性能 CPU 先运行，起步使用约 8 个求解 worker，并测量内存与时间。需要同时跑多组实验时，优先考虑高主频、多核心 CPU 和足够内存，而不是显卡。

**最终结论：不租 GPU。**

## 14. 第一个里程碑：Gate-0

### 14.1 Gate 是什么

**选择 C：统一物理模块验证与 Q1 基础结果组成同一个 Gate-0。**

具体为：

```text
原始输入齐全
＋关键物理公式来源核实
＋地形、飞行、能耗、充电独立核验
＋45项安全载荷证据
＋第一份80箱完整可行Q1组批
```

Gate-0 不要求先把 Q1 的全部论文图表做完，也不要求所有次级目标都求到最优；但不能只检查“程序没有报错”。

### 14.2 为什么它会污染后面所有问题

```text
DEM 最大值错误
→ 巡航与爬升高度错误
→ 飞行时间和能耗错误
→ Q2 交付、返航和电池充电时间错误
→ Q3 运输与中继无法真正同步
→ Q4 资源峰值和缺口错误
```

同样，若满电复用时间算短，Q2 看起来资源充裕，Q3 看起来中继充足，Q4 看起来无需增配，实际上全部建立在错误资源时间线上。

### 14.6 每一个数怎么算

**第一步：核对地理输入。**

记录 O01、服务区的原始经纬度、节点海拔、DEM 所在像元和坐标系。米制投影固定在公共坐标模块，不能各问自行选择距离算法。

对每条航段输出全部所经像元及其高程：

$$
H^{max}_{ij}
=
\max_{c\in Cells(i,j)}H_c.
$$

再计算：

$$
H^c_{ij}=H^{max}_{ij}+50.
$$

节点作业高度：

$$
z_{O01}^{op}=z_{O01}^{ground},
\qquad
z_i^{op}=z_i^{ground}+30.
$$

爬升与下降高度：

$$
h^+_{ij}=H^c_{ij}-z_i^{op},
\qquad
h^-_{ij}=H^c_{ij}-z_j^{op}.
$$

若出现负值，触发数据或规则冲突，不使用 `max(0,·)` 静默掩盖。

**第二步：核对飞行时间。**

$$
t_{gij}
=
\frac{h^+_{ij}}{v_g^\uparrow}
+
\frac{d_{ij}}{v_g^c}
+
\frac{h^-_{ij}}{v_g^\downarrow}.
$$

准备、交付和周转分别列出，不能混进“纯飞行时间”后失去追踪。

**第三步：核对载荷相关航程。**

$$
L_g(q)
=
L_g^0-
(L_g^0-L_g^F)
\left(\frac{q}{Q_g}\right)^{3/2}.
$$

应满足：

$$
L_g(0)=L_g^0,\qquad L_g(Q_g)=L_g^F.
$$

**第四步：核对能耗。**

$$
E^{RT}_{ig}(q)
=
E^{hor}_{Oi}(q)+E^{up}_{Oi}(q)
+
E^{hor}_{iO}(0)+E^{up}_{iO}(0).
$$

其中 \(E^{hor}\)、\(E^{up}\) 的具体展开必须来自已经核实的参数说明或明确声明的补充模型。

通常会遇到“按可用能量与等效航程折算水平能耗”“按总质量、爬升高度与效率折算爬升能耗”这类关系，但在核实前，**不能把它们作为官方默认实现**，尤其不能猜测爬升参数是效率、损耗系数还是其他定义。

**第五步：核对 SOC 与安全边界。**

$$
SOC_{\mathrm{return}}
=
1-\frac{E^{RT}_{ig}(q)}{E_g^{use}}.
$$

检查：

$$
SOC_{\mathrm{return}}\ge\rho_g.
$$

能量限制型的二分证据必须包含：

$$
E(q_L)\le E_{\mathrm{budget}},
\qquad
E(q_U)>E_{\mathrm{budget}},
\qquad
q_U-q_L\le0.001\text{ kg}.
$$

额定质量限制型则验证 \(q^*=Q_g\) 仍可行，不要求再增加载荷测试。

### 14.7 差多少算通过

| 检查量                   | 通过标准                                                 |
| ------------------------ | -------------------------------------------------------- |
| 文件、对象编号、参数来源 | 完全一致，无缺项                                         |
| 航段穿越像元集合         | 独立算法结果一致；边界接触规则一致                       |
| DEM 最高高程             | 同一原始栅格下差≤0.001 m，且能指出最高像元              |
| 水平距离                 | 同一声明坐标度量下差≤0.01 m                             |
| 巡航、爬升、下降高度     | 差≤0.01 m                                               |
| 飞行时间                 | 独立程序差≤0.001 s；人工四舍五入复算差≤0.1 s           |
| 能耗                     | 独立程序差≤\(10^{-6}\) kWh；人工复算差≤\(10^{-4}\) kWh |
| SOC                      | 人工复算差≤0.01个百分点；程序使用更严格内部精度         |
| 安全载荷                 | 二分夹逼区间≤0.001 kg，且可行端与不可行端判定正确       |
| Q1 货箱覆盖              | 80箱各一次                                               |
| 安全约束                 | 不能靠上述“人工显示误差”容忍实际超限                   |

距离的 0.01 m 标准是**同一度量方法的实现一致性**，不是要求投影距离与大地线距离完全相同。两种度量的差异应单独记录为坐标近似检查。

## 19. 止损方案

| 情况                     | 明确降级动作                                                                               |
| ------------------------ | ------------------------------------------------------------------------------------------ |
| 原始数据或能耗定义缺失   | 停止正式数值计算；完成输入清单、测试骨架与缺失报告，不编参数                               |
| Q1安全载荷迟迟不可信     | 停止Q2，检查DEM最高值、去返程载荷、能量单位与余量                                          |
| Q1枚举过大               | 按服务区独立求解，加强质量、体积和能量剪枝；先保留完整可行组批，未完成证明时不声称精确最优 |
| Q2 route pool爆炸        | 活跃池回到2000以内，保留现有可行解与关键箱替代项，只增量补困难任务                         |
| CP-SAT可选任务接口过复杂 | 暂时固定一套完整单/双点任务集合，只解资源与时间；仍使用同一引擎                            |
| CP-SAT简化后仍未跑通     | 使用确定性最早可用双资源排程取得候选，只有Validator零硬违规才可作为降级解                  |
| Gurobi许可证失败         | Q1立即切HiGHS，Q2/Q3不变                                                                   |
| Q3候选超过1500           | 先做回传、能量、覆盖相关性与保守支配筛选，不再全域增点                                     |
| Q3一直不能覆盖           | 分清“几何无覆盖”和“有覆盖但排不出”；前者定向细化，后者错峰、缩窗或拆运输任务           |
| 连续验证出现未认证区间   | 加密或换成余量更充足的保障方案；不能改成默认通过                                           |
| 求解器太慢               | 设时限保留最好完整可行解，缩小活跃池，不为了0.1%改进拖延整题                               |
| Q4连通分量不足3个        | 给结构性不可分证据；在Q3正式冻结前回退修改，不能在Q4暗改                                   |
| 临近提交                 | 停止核心重构，只修验证失败、输出错误和论文不一致                                           |

对于已经得到完整可行的 Q3，连续两轮修复没有改善当前目标元组，就停止扩大搜索，转向验证与论文证据。
